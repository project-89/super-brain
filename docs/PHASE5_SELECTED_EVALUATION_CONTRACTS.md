# Selected local evaluation bundles

This format contains explicitly selected, sanitized evaluation bytes. It does not reuse the private backup exporter, discover local files, execute generated code, or publish anything. `@_89/fold-eval` supplies a bounded format, SHA-256 hashing, deterministic report generation and complete self-verification. The harness owns provider execution, independent check observations, annotation and filesystem writes.

## Shared artifact ports

`EvaluationArtifact` is `{path, mediaType, content}`: a safe logical path under `artifacts/`, an allowed text/JSON/JavaScript/Markdown media type, and exact UTF-8 text. `evaluationArtifactRef(artifact)` returns `{path,sha256}`. Files are limited to 2 MiB each and 16 MiB of selected content; attempts are limited to 100 and three submissions each. The format retains all selected rounds, while acceptance summarizes the final actual submission.

`FrozenEvaluation` contains `id`, `taskId`, `taskVersion`, `inputStateId`, `oracleVersion`, `treeVersion`, `annotationVersion`, `frozenAt`, and exact `task`, `input`, `oracle`, `tree`, `rubric` artifact references. Optional `supportingArtifacts` retains the frozen public examples, checker/driver source, and other explicitly selected implementation witnesses. The oracle artifact is JSON containing either the frozen case array with unique `id` fields, or `{version:1,suiteVersion,checkIds}`. Case IDs must be nonempty and unique. Task and annotation version declarations must match every selected attempt; hash references must match actual bytes. Attempts may not predate the recorded freeze time. The format cannot independently attest that a supplied timestamp was historically truthful.

`SelectedEvaluationAttempt` identifies `kind` (`real-provider`, `synthetic-fixture`, `preparation-failure`), condition (`no-memory`, `memory`), the exact frozen versions, start/finish times, runtime provider/configured model/observed model/runtime version, and a sanitized configuration artifact. Each submission references exact model output, optional extracted code, checks, optional observed duration and source-provided usage. Unknown observations stay absent. A real provider attempt requires an observed submission. A preparation failure has none.

Every real provider submission also contains `runtime:EvaluationRuntime`, preserving that round's provider, configured/observed model, runtime version and configuration artifact. The report derives `runtimeConsistency` as `consistent`, `mixed` or `unavailable`. A mixed attempt does not present one final-round model as its sole observed identity. Unknown observations stay unavailable. Configuration identity uses its bytes, not a logical filename; copying a file cannot change comparability. Per-round observations remain in the manifest even when the attempt's declared runtime summary differs.

Annotations use `{version:1,annotationVersion,annotations:[{stepId,assignment,evidence,note?}]}`. The exporter validates frozen manual rubric methods, mapped/ambiguous node IDs, code hashes and one-based inclusive line bounds, exact output/check references, and actual step IDs: the submission ID or its `:checks` suffix. Evidence must belong to the same observed round; later fixes cannot be assigned retroactively to an earlier step. Semantic mapping requires both a concrete code span and an observed check. Ambiguous/unmapped assignments remain explicit; absent annotations count as missing, rather than invented decisions. The report exposes structural, semantic, ambiguous, unmapped and missing mapping counts.

`EvaluationChecks` contains `{version:1,suiteVersion,codeSha256?,availability,checks,reason?}`. `availability` is `completed` or `unavailable`; each check has `{id,status,detail?}`, where status is `passed`, `failed` or `unavailable`. When a submission has code, `codeSha256` must match that exact code artifact. Unknown and duplicate check IDs fail verification. Missing frozen checks become unavailable. A completed empty/partial suite, absent code, or unavailable execution yields `acceptance:"unavailable"` and `confidence:null`; it never exposes the arithmetic kernel's all-absent neutral value as success. Available confidence is a mechanical 0/1 aggregation of the frozen suite, not a calibrated probability. Completed check counts remain visible even when the aggregate is unavailable. Actual failed checks remain separate from a model's own outcome label. This is automated evidence, never human approval.

For the memory condition, `memory` identifies the exact `{memoryId,revision}`, `recallId` and injected artifact. The same revision must appear in selected eligible sources. Retrieval and prompt injection demonstrate exposure only; they do not demonstrate the model's internal use. The harness retains the real authenticated recall subject privately and uses synthetic labels in the local dataset.

## Authorization and redaction boundary

`SuperBrainClient.selectEvaluationSources(request, RequestOptions?)` calls `POST /evaluation-sources/selection` in the normal tenant route. The request is:

```ts
{
  selectionId, audience: "local-reviewed", redactionVersion,
  expectedSubject: { organizationId, workspaceId, principalId },
  references: [{ kind: "memory", memoryId, revision } | { kind: "event", eventId }],
  reviewedReferences: [/* exact explicitly reviewed subset */]
}
```

The server re-resolves membership and requires that the actual account equals `expectedSubject`. A changed account returns `409 evaluation_subject_changed`. Memory selections require `memories:read`; canonical event selections additionally require `trajectories:read`. Platform inspection does not confer export authority. The SDK supports at most 100 distinct references from one currently authorized snapshot. It excludes unreviewed, stale, unresolved, superseded, transitively invalid, forgotten or inaccessible memory sources. Missing and denied references share the same exclusion reason so the result does not reveal private existence or dependency details.

Event selection supports immutable canonical task manifests, attempt manifests, outcomes and interventions. It uses current scope authorization and excludes records whose exact dependent memory revisions are now invalid. It preserves selected historical event identity, rather than relabeling old evidence as a current revision. Referenced private artifacts remain declarations; neither this endpoint nor an artifact ID proves their bytes exist or grants permission to disclose them. Other event kinds are explicitly unsupported.

The result contains selected snapshots without raw capture envelopes/actor account IDs and exclusion reasons. Its authenticated subject is a **private authorization receipt**, never a bundle artifact. Selected source content still requires a second byte-level redaction review: arbitrary text can contain sensitive material. Before final bundle creation, the harness refreshes eligibility for every selected canonical source and excludes any newly unavailable source. An offline bundle cannot discover future revocation. Re-export requires fresh selection. Pure format functions validate selection declarations and byte consistency, not a signed server authorization token.

`SelectedEvaluationInput` provides frozen metadata, attempts, selected artifacts, eligible source references, explicit exclusions, and `review:{selectionId,audience:"local-reviewed",redactionVersion,reviewedArtifactPaths,reviewedBy,reviewedAt}`. Reviewer labels must be synthetic. Every referenced artifact must be reviewed, and every supplied artifact must be referenced. The exporter rejects common credential fields, raw headers, account identity fields and private home paths; this is an additional guard, not automatic proof of complete redaction. Removed source labels in exclusions must themselves be safe synthetic identifiers. Only the local reviewed audience is currently supported. External publication needs a separate explicit process.

## Regeneration and interpretation

`createSelectedEvaluationBundle(input)` returns `{files,manifest,report}`. The files include selected bytes plus canonical `manifest.json`, `report.json`, `report.md`, `dictionary.json`, and a manifest digest. Filesystem writing belongs to the caller. `verifySelectedEvaluationBundle(files)` rejects missing/extra/tampered files, mismatched versions/references, unexpected metadata, and any derived output that differs from independent regeneration. `regenerateEvaluationReport(files)` returns the independently regenerated report only after complete verification. These functions never execute code. Hashes establish internal byte consistency, not authorship; an attacker who replaces the entire bundle and all hashes needs an independently retained digest to be detected.

Comparison groups include exact task/input/condition/provider/configured and observed model/runtime/configuration identity. Memory conditions remain separate. The report presents observed check outcomes, submissions, durations, and missing evidence; it does not invent token counts or combine source-provided usage observations into unsupported totals. One task and four real attempts form a bounded representation/reproducibility experiment, not a causal memory-effect claim or a model leaderboard. Synthetic unit tests and isolation probes remain visibly synthetic.

The harness first writes a private selection preview and its content hash. Final local bundle creation requires that exact reviewed hash, after refreshing canonical source eligibility. Changing selected bytes invalidates the review. The preview is a review request, not a published dataset; the final approved bundle retains the actual review metadata. Raw runtime streams, headers, private source receipts and unrelated corpus content remain outside both selected artifact inputs and generated reports.
