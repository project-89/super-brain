# Observable trajectory annotation rubric — version 1

Freeze this rubric and tree before inspecting provider output. The tree represents task requirements and legitimate alternatives, not internal model reasoning.

A real attempt contains only observed submissions, module bytes, fixed-driver invocations and actual check results. Preserve configured and observed runtime/model identities separately. A model summary is self-reported text; it cannot certify a decision, hidden reasoning, success, human approval or semantic equivalence.

The artifact envelope is `{version:1,annotationVersion,annotations:[...]}`, where annotationVersion is the frozen rubric hash/version. Each annotation has `{stepId,assignment,evidence,note?}`. Use existing fold-trace ProjectionAssignment: mapped `{kind:"mapped",nodeId,method}`, ambiguous `{kind:"ambiguous",candidates:[nodeA,nodeB,...],reason,method}`, or unmapped `{kind:"unmapped",reason,method}`. Method is `{kind:"manual",id:"frozen-observable-rubric-v1",basis:"structural"|"semantic"}` without an invented numeric confidence. Evidence is a nonempty array of `{kind:"code-span",artifactSha256,startLine,endLine}`, `{kind:"check",caseId,roundId}`, or `{kind:"submission",artifactSha256,roundId}`. Lines are one-based inclusive. Every referenced artifact/check must exist in the selected attempt. A code-span hash identifies the exact submitted code; a submission hash identifies the observed provider-output artifact. roundId is the actual submission ID, and stepId must name a real trace step. An unavailable check can justify an unmapped observation but cannot establish program behavior.

Structural mapping identifies an observable operation, code structure or completed check. Semantic mapping adds reviewer interpretation of behavior and must cite a concrete expression/branch and relevant observed checks; it is not an observed mental state. Exact BigInt arithmetic and canonical decimal length/lexicographic comparisons are equally valid. Stable serialization and recursive JSON equality are equally valid alternatives.

Map each submission/check step only to what the whole observed step supports. Use ambiguous candidates or an unmapped reason when several nodes fit, retaining specific code-span notes. Never split one response into invented chronological actions. A later patch is a new actual submission, not evidence of an earlier internal decision. Tree paths are an analytic guide, not mandatory code order; correct alternatives are not penalized for a different structure.

Acceptance comes from the independent frozen executable oracle. Missing driver/provider, truncated output and unexecuted checks are unavailable, never passing. Preserve completed partial checks but mark incomplete aggregate acceptance unavailable. Keep a model's own outcome label separate.

Compare only exact task versions, initial fixture hashes, oracle hashes and conditions. Report memory/control conditions separately with actual injected bytes, recall IDs and exact memory revisions. One task and a small sample cannot establish a model ranking or causal improvement. Unknown usage stays unknown; infer no token counts, costs or unobserved actions.
